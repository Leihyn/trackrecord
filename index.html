Trackrecord

A prediction agent's record that nobody, including the agent, can pad.

Every forecasting agent advertises a hit rate, and none of them can be checked. Losses get quietly dropped, wins get backfilled, and calls that were never made appear afterwards. The record is written by the party it flatters.

A hold invoice inverts that. The grader picks a secret and gives the agent only its hash, so the agent issues an invoice it cannot settle. The grader releases the secret only for calls that turned out right. Getting paid therefore is the proof, and every settled invoice leaves behind a preimage anyone can check against the hash. Everything here runs in this tab: real signed testnet BOLT-11 invoices and SHA-256 proofs. No server, no node, no wallet.

sheet i The calls, as filed

Each call gets an invoice whose payment hash comes from the grader. The agent never sees the preimage behind it, so none of these can be settled yet.

sheet ii Resolution

The grader checks each call against what happened, and releases the secret for the ones that were right. It does nothing at all for the others — there is no punishment step, just an absence.

sheet iii Audit, performed by the reader

Every row below is verified here, in your browser, by hashing the preimage and comparing it with the invoice's payment hash. Nothing is taken on trust.

sheet iv The padded row

Now the agent adds a win it never earned, and invents the receipt to go with it. The same audit runs again.

closing Why you do not have to believe the agent

Because it cannot mint a receipt for a call it got wrong. Settling needs a preimage only the grader holds, and SHA-256 does not run backwards. It cannot quietly drop a loss either, because a loss is simply an invoice with no preimage, and an absence is as visible as a presence when the record is the full set of invoices rather than a list the agent curates. The one party you do have to trust is the grader, to judge outcomes honestly.

Implemented: hold-invoice semantics where the payment hash is supplied by a third party, BOLT-11 invoice construction on testnet with a real recoverable signature, preimage-to-hash verification of every receipt, and an audit that anyone can re-run. Not implemented: routing or settling a real Lightning payment, HTLC timeouts and refunds, and the grader's own accountability, which here is assumed. No node is contacted and no payment is made, so this page cannot move a satoshi on any network.
